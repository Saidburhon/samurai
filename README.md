# qilich.com

The site of **Qilich** ("sword" in Uzbek), a Japanese IT agency now in Tashkent. One sword is the whole page: a
Japanese blade with an Uzbek grip, drawn as an oshigata, filled with steel, forged, quenched, polished and sheathed as
you scroll (the HITOFURI direction). Static site on Cloudflare; everything visual is made in code (SVG, canvas, WebGL).

The build is staged by gates. **G0 (this state)** ships the skeleton and all the content in **flow mode**: a printed
sword catalogue, one ink plate per scene, the same text as the film. The WebGL film (cinema mode) arrives from G1;
`scripts/build.mjs` keeps it off (`CINEMA = false`) until then.

## Pages and languages

| URL | Language | Source |
|---|---|---|
| `/` | Uzbek | `public/index.html`, edited by hand (its generated parts are rewritten by the build) |
| `/ru/`, `/en/` | Russian, English | generated from the Uzbek page with `scripts/i18n.mjs` |
| `/ja/` | Japanese | generated the same way from `JA` in `scripts/i18n.mjs`: an original page for Japanese companies looking for an offshore development partner, not a translation |
| `/about/`, `/contact/`, `/privacy/`, `/press/` and their `/ru/`, `/en/`, `/ja/` twins | all four | generated by `scripts/build-pages.mjs` from `scripts/pages/copy-company.mjs` (words), `scripts/pages-i18n.mjs` (chrome) and `content/site.json` (facts) |
| `/404.html`, `/ru/404.html`, `/en/404.html`, `/ja/404.html` | Uzbek; Russian, English, Japanese | `public/404.html` by hand; the others generated by `scripts/build-pages.mjs` |

- Text lives in `data-i18n` elements (`data-i18n-label` for `aria-label`). The build fails on a key missing from a
  dictionary and on a dictionary key the page no longer uses.
- Every string JavaScript shows is in the HTML (`#strings`), so the dictionaries, the lint and the font subsets see it.
- Copy rules (checked by `scripts/lint-copy.mjs`): never any form of "yaratish"; no product or client names; no
  Telegram handle; the Uzbek okina is `ʻ` (U+02BB); Russian puts a non-breaking space before every dash.
- Titles, descriptions, share images and JSON-LD per language: `META` in `scripts/build-langs.mjs`.

## Search engines and AI assistants (SEO-GEO-GUIDELINES with SEO-GEO-DECISIONS)

- **Company facts** live in `content/site.json`: legal name, founding year, representative, street address, people,
  certifications, `sameAs` profiles, the Japanese entity, the analytics IDs. Everything is empty until the owner fills
  it in; an empty fact is hidden on every page and left out of the JSON-LD (nothing is ever invented or shown as a
  placeholder). The one-sentence company description per language is there too: it is the Organization
  `description`, the press page's one sentence and the start of `llms.txt`.
- **Every page** (`scripts/site.mjs` `headLinks`, `scripts/pages/ld.mjs`): one title and description of its own, one
  h1, a self canonical, reciprocal hreflang for all its twins plus `x-default` (the English twin), `og:locale` with
  `og:locale:alternate`, and one JSON-LD `@graph`: the same Organization (`https://qilich.com/#organization`) and
  WebSite (`#website`) nodes everywhere (only the description is translated), a WebPage/AboutPage/ContactPage and a
  BreadcrumbList below the homes. The language switch names each language in its own script (Oʻzbekcha, Русский,
  English, 日本語) and links to the same page in that language.
- **Site files**, written by the build: `/sitemap.xml` (a sitemap index) → `/sitemaps/{uz,ru,en,ja}.xml` (canonical
  URLs with the day their words last changed, kept in `content/lastmod.json`; no `xhtml:link`), `robots.txt` (every
  search and AI agent of the decisions file named and allowed, only `/api/` closed), `llms.txt`, and the IndexNow key
  file `/<key>.txt`. After a deploy, `npm run indexnow` sends the changed URLs to Bing and Yandex
  (`-- --dry-run` to see them, `-- --all` for the first time); it records what it sent in `content/indexnow-sent.json`.
- **Analytics** (GA4 in consent mode, Yandex Metrika) ship only when an ID is set in `content/site.json`: the build then
  adds the loader (`src/ui/analytics.js`), its config and a consent banner to every page. Nothing loads and no cookie
  is set before the visitor allows it; the banner appears only after a scroll and never moves the layout. Events:
  `generate_lead` (contact form), `contact_click` {method: phone, email, telegram, whatsapp, line}, `cta_click`
  {page, lang, cta}. Mark `generate_lead` as a key event in GA4.
- **The contact form** works without JavaScript (a `mailto:` form, post, text/plain); with JavaScript it opens a tidy
  prefilled email, or posts to `/api/lead` once `lead.api` is `true` in `content/site.json` (the Worker route exists;
  it needs the TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID secrets). `generate_lead` carries `method`: `api` or `mailto`.
- **The privacy policy** is written in plain terms from what the site does and is marked for legal review (a comment at
  the top of its `<main>`): Uzbekistan's Law ZRU-547 with its data-localisation rule, and Japan's APPI (cross-border
  transfer, the operator's address and representative).
- **Owner tasks** (not code): verify the domain in Google Search Console, Bing Webmaster Tools and Yandex Webmaster (DNS
  records in Cloudflare) and submit `https://qilich.com/sitemap.xml` in each; turn off Cloudflare's AI-bot blocking and
  Bot Fight Mode for the public site; in GA4 add a custom channel group "AI assistants" (source matches
  `chatgpt\.com|perplexity\.ai|gemini\.google\.com|copilot\.microsoft\.com|claude\.ai`), placed above Referral;
  have the Japanese copy read by the Japanese partner before launch (`npm run qa:ja -- --all` records an independent
  model review of every Japanese string, the catalogue and the blog included, in the meantime); in Cloudflare, zone
  qilich.com → SSL/TLS → Edge Certificates, set **Always Use HTTPS** to On (http:// must answer 301 to https://);
  after changing `workers/www-redirect/` run `npm run deploy:www` (www and http go to https://qilich.com in one hop);
  turn on Cloudflare AI Crawl Control or Bot analytics and note each month how often OAI-SearchBot, PerplexityBot,
  Claude-SearchBot, Bingbot and Googlebot fetched the site, with 200 responses, not challenges.
- **Addresses** (`public/_redirects`, written by the build): every page has one address with a trailing slash; the
  no-slash form and `/index.html` answer 301 to it (Cloudflare's own answer would be a 307). A catalogue page that a
  language does not offer (the Japanese catalogue offers only what a company in Japan buys: `scripts/pages/ja-market.mjs`)
  answers 301 to that language's catalogue. Each language folder has its own 404 page (`/ru/404.html`, `/en/404.html`,
  `/ja/404.html`, noindex); the root `/404.html` is hand-made.
- **Content-Security-Policy** (report-only, `public/_headers`, written by the build with the hash of every inline
  script): it blocks nothing yet; the browser console lists what it would block. Enforce it (rename the header to
  `Content-Security-Policy`) after a GA4 real-time test with the real IDs.
- **Checks:** `npm run qa:seo` (`scripts/qa/seo-check.mjs`: crawls every page over HTTP without JavaScript and fails on
  a duplicate title, a missing or second h1, a non-reciprocal hreflang, an unparsable or inconsistent JSON-LD, a
  sitemap, robots.txt or 404 problem) and `npm run qa:pages` (`scripts/qa/pages-probe.cjs`: every page in a browser at
  four sizes, console, overflow, clipping, the switch, the Japanese font stack, the form with and without JavaScript;
  `-- --analytics` on a build with test IDs checks the banner and the events). `npm run qa:launch` (`scripts/qa/launch-check.mjs`)
  checks the addresses over HTTP: against `npm run dev` (`-- http://localhost:8787`) the 301s of `public/_redirects` and
  the 404; against https://qilich.com after a deploy also http → https and www → apex in one hop.

## Build

```bash
npm install
npm run build     # everything below, in order
npm run lint      # the copy lint over the sources and the built pages
```

`npm run build` (`scripts/build.mjs`):
1. `lint-copy.mjs`
2. `build-osh.mjs`: every drawing from the one generator (`src/sword/drawing.js`, geometry in `src/sword/geom-core.js`,
   the girih in `src/sword/girih-holes.json`): the inline hero, plan and bookend drawings (`<!-- gen:osh -->`), the
   dial (`<!-- gen:dial -->`, `src/sword/dial.js`), the CSS that places the hero drawing without JS
   (`src/styles/gen/osh.css`) and the flow-mode plates (`public/assets/osh/*.svg`, no text inside)
3. the inline head and boot scripts (`src/boot/`) and the critical CSS, written as whole `data-gen` elements
4. esbuild: `src/main.js` and `src/styles/main.css` into `public/assets/build/` (hashed, split chunks)
5. `build-langs.mjs`: `/ru/`, `/en/`, `/ja/`, META, JSON-LD, hreflang; `build-pages.mjs`: the company pages in four
   languages, the sitemaps, `robots.txt`, `llms.txt`, the IndexNow key, the analytics block
6. `fonts.mjs`: subsets made from the built pages (Geologica, Martian Mono, Zen Old Mincho, QOkina for the okina,
   GeologicaSign), metric-matched fallbacks, `<style data-gen="fonts">`. Source fonts are fetched once into `.cache/`.
7. the preload block of each page (`<!-- gen:preload -->`)
8. `og.mjs`: share images and icons, only when the hero or the h1 changed

The build output is committed. `scripts/girih.mjs` re-traces the girih polygons (run once; the JSON is committed).

## Look at it

```bash
python3 -m http.server 8800 -d public      # http://localhost:8800/  (?tier=0 forces flow mode)
npm run dev                                  # wrangler, same runtime as production
```

QA probes (global Playwright, the capture's SwiftShader flags): `npm run qa:fit` (text against margins, other text,
the nav and ruler bands and the blade band, uz/ru/en at 1440 × 900, 1280 × 720, 390 × 844, 360 × 740) and
`npm run qa:flow` (console, lang, h1, all copy, the okina's font, the no-JS drawing on its diagonal, overflow, sheets).

## Deploy (Cloudflare, static assets)

`npm run deploy` builds, then `wrangler deploy` uploads `public/` to the `qilich-com` Worker (custom domain
`qilich.com`). `public/_headers` makes every hashed asset immutable. `npm run deploy:www` deploys the
`www` → apex redirect in `workers/www-redirect/`.
